00 · ABSTRACT

Abstract

Content teams often need to decide which webpages deserve attention first when a large content inventory shows mixed search and engagement performance. This study investigates whether historical search-performance, traffic, engagement, content, and freshness signals can support a practical prioritization workflow for content-refresh review.

The analysis uses an anonymized dataset containing 30,000 webpages across 32 clients. The decision problem is to identify which webpages should be reviewed sooner rather than later, so that content and SEO teams can focus their limited review effort on the pages showing stronger evidence of observed decline.

The modeling task is formulated as binary classification followed by ranking. The target identifies webpages associated with an observed declining trend. Logistic Regression is evaluated against the ML-07 rule-based baseline using a client-grouped holdout design, with 23,837 training rows from 25 clients and 6,163 testing rows from 7 unseen clients.

On the recorded grouped evaluation, Logistic Regression achieved Precision@20 of 1.00 and Precision@50 of 1.00, compared with 0.55 and 0.48 for the ML-07 rule baseline. The resulting scores provide evidence for ranking and prioritization on this evaluated dataset and split.

Practical takeaway: The model can be used as a decision-support signal to help organize webpage review priority. It does not determine whether a page should ultimately be refreshed, and the recorded evaluation does not establish that refreshing a page will cause improved search performance.
00.5 · INTRODUCTION

Introduction

The content-refresh problem is fundamentally a prioritization problem. A content or SEO team may have many webpages to review, but not every page requires the same level of attention at the same time. The goal of this project is therefore not simply to predict a label, but to turn available search and engagement signals into a useful ranking of webpages for human review.

This study focuses on webpages whose observed performance indicates a declining trend. The dataset contains 30,000 unique content items across 32 clients, with historical search, traffic, engagement, content, and freshness signals. These signals provide the evidence used to distinguish pages that may deserve earlier review from pages that can be monitored or left without immediate refresh effort.

To test whether a machine-learning approach can improve this prioritization, the project compares the ML-07 rule-based baseline with a Logistic Regression model. Evaluation is performed using a client-grouped split so that the testing clients are not present in the training data. This creates a clearer test of whether the ranking approach can identify declining webpages for clients that were not used for training.

The recorded evaluation shows a substantial improvement over the baseline: Precision@20 increases from 0.55 to 1.00, while Precision@50 increases from 0.48 to 1.00. These results support using the model output as a prioritization signal for the next stage of human review.

How this fits the content workflow: Search and engagement signals → model-based prioritization → ranked review queue → human content assessment → refresh, monitor, or no-action decision.

The model is intentionally treated as decision support rather than an autonomous content decision-maker. The analysis is observational, the target is derived from observed trend direction, and the evaluation uses one fixed grouped client split. Therefore, the results should be interpreted as measured evidence from this project rather than as causal proof or a guarantee of future performance.

01 · RESEARCH QUESTION

Research Question

Question

Which webpages should be prioritized for content refresh based on search performance and engagement metrics?

Decision

Determine which webpages should be reviewed first for potential content improvement.

Action

An SEO or content team can review, update, rewrite, expand, or monitor the selected webpages.

Unit of Analysis

One webpage, represented as one content item in the dataset.

Cost of a Wrong Recommendation

A false priority can waste content-team effort on pages that do not need immediate improvement while allowing genuinely declining pages to receive less attention than they deserve.

03 · METHODOLOGY

Methodology

Target

The modeling target is is_declining_label. It represents whether the observed webpage trend is classified as declining.

Target construction:
trend_direction = "down" → declining label = 1
Other observed trend directions → declining label = 0

Model

The primary ML-11 model is Logistic Regression. Its output score is used to rank webpages for evaluation and prioritization.

Features

The final model uses 28 predictive features drawn from historical search, traffic, engagement, content, freshness, and performance signals.

Grouped Client Validation

The dataset is split by client_id, rather than randomly mixing rows from the same client between training and testing. This prevents client-level overlap between the two evaluation groups.

Leakage Controls

05 · LIMITATIONS

Limitations & Honest Framing

  • The data is observational and does not establish causality.
  • The target is derived from observed trend_direction rather than an independently verified business outcome.
  • The evaluation uses one fixed grouped client split.
  • The strong 1.00 Precision@20 and Precision@50 results should not be assumed to hold for every future client, time period, or dataset.
  • Results may change when the underlying data distribution changes.
  • A model score identifies a prioritization signal; it does not determine the final content action automatically.
  • A recommendation to refresh content is not evidence that the refresh itself will cause improved search performance.
Claim boundary: This project provides measured, directional decision-support evidence for webpage prioritization. It does not provide causal proof.
